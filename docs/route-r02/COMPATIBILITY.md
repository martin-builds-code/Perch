# R02 mobile and Safari compatibility

The existing build still targets `safari15` for JavaScript and CSS. R02 adds no runtime dependency, animation library, file-picker API or permanent telemetry. The aircraft display's existing landscape/iPad checks remain in place; only `/route-review` uses a separate mobile scrolling layout.

Published [MDN browser-compatibility data](https://github.com/mdn/browser-compat-data) was read on 11 November 2026; the relevant fields are saved in [safari-api-support.json](safari-api-support.json). It lists Safari file-sharing support in `share`/`canShare` from version 14, anchor download support from 10.1, and iOS `Blob.text()` support from 14.5. These predate the target iPadOS 15.8.5. Local storage and object URLs are older baseline facilities. [MDN canShare](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/canShare) explains why file support must be checked at runtime; [download](https://developer.mozilla.org/en-US/docs/Web/API/HTMLAnchorElement/download) expresses a download intention, not a guarantee that the user saved the file.

The export runs directly from a tap, checks native file sharing, and otherwise uses a JSON Blob with an object URL and download anchor. An explicit Download file instead button handles unavailable/refused sharing. A cancelled share does not automatically create a download or clear the draft. One bounded object URL is revoked on replacement/unmount. Draft-storage exceptions are handled; an export/import file is the cross-device recovery mechanism. Clipboard copying has a selectable-text fallback.

Phone browser checks cover 320×568 and 390×844; iPad landscape covers 1024×768 and 1024×624. Both mocked failure cases and the actual hosted frozen dataset are checked. Their results are in `browser-tests.json`, `hosted-checks.json`, and the accompanying screenshots. The inherited normal display checks include all 51 Stage 3 scenarios, stationary artwork, PIN/sleep pixel comparisons and R01/secondary request lifecycle behavior.

No physical iPhone/iPad or Safari-engine run was performed. Device-specific share-sheet/Files behavior, private-storage restrictions and Guided Access may affect export; these remain physical acceptance checks. The downloadable-file fallback is provided rather than assuming native sharing is universally available. Opening the historical FR24 links still depends on legitimate account/history access. No FR24 automation or credentials are embedded.
